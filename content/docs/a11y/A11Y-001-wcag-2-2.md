# A11Y-001 — WCAG 2.2

## Summary
WCAG 2.2 defines testable A/AA/AAA criteria; use Level AA as the project baseline and validate new 2.2 additions manually, not by scan alone.

## MUST
- A11Y-001.M1: State the conformance target (WCAG 2.2 Level AA) and scope for each feature before audit.
- A11Y-001.M2: Assess new 2.2 AA criteria: 2.4.11 Focus Not Obscured (Minimum), 2.5.7 Dragging Movements, 2.5.8 Target Size (Minimum), 3.2.6 Consistent Help, 3.3.7 Redundant Entry, 3.3.8 Accessible Authentication (Minimum).
- A11Y-001.M3: Include keyboard, screen reader, zoom/reflow and high-contrast checks alongside automated scans.

## SHOULD
- A11Y-001.S1: Document exceptions and any AAA criteria considered but not required.
- A11Y-001.S2: Re-test after UI changes affecting focus, input, help or authentication.

## AVOID
- A11Y-001.A1: Do not claim conformance from an automated scan alone.
- A11Y-001.A2: Do not label AAA as AA or treat advisory techniques as requirements.

## DECIDE
| Situation | Decision |
|---|---|
| Conformance target unclear | Define AA scope with team before design |
| New 2.2 criterion not applicable | Document rationale and exception |
| Automated scan passes | Continue manual keyboard/AT review |

## STATES
- Conformance scope
- Automated scan
- Keyboard review
- Assistive tech review
- Reflow/zoom
- Exception recorded

## EXAMPLE
Good: "Audit notes SC 2.5.8 target size 24x24 CSS px and documents a justified exception." Bad: "Lighthouse 100 means WCAG compliant."

## FAILURE MODES
- Automated tools catch only a subset; manual checks find focus obscurity and auth barriers.
- Treating AAA as AA inflates conformance claims.
- New 2.2 criteria are often missed in legacy checklists.

## CHECK
- [ ] Conformance target stated?
- [ ] New 2.2 AA criteria checked?
- [ ] Manual keyboard/AT included?
- [ ] Exceptions documented?
